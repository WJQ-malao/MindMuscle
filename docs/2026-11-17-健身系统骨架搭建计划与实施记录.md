## 1. 技术选型与决策记录

### 1.1 总览

| 层 | 选型 | 备选 | 决策理由 |
|---|---|---|---|
| 后端框架 | Spring Boot 3.4 + JDK 21 | - | 题目要求 |
| AI 框架 | Spring AI 1.0.0（正式版） | LangChain4j | Spring 官方出品，与 SpringBoot 自动配置无缝；LangChain4j 的 RAG 管道功能更全（查询改写/rerank），评估后认为对毕设属锦上添花，写进论文展望章节 |
| 对话模型 | DeepSeek 官方 API（deepseek-chat） | 硅基流动托管的 DeepSeek | **DeepSeek 官方无 Embedding 模型**，Embedding 必须另找供应商；对话直连厂商， Embedding 单独走硅基流动，两者用 Spring AI 一个 OpenAI 兼容客户端 + 一个自定义 Embedding Bean 解决 |
| Embedding | 硅基流动 BAAI/bge-m3（1024 维） | bge-large-zh-v1.5 | bge-m3 多语言、长文本支持更好；维度与 Milvus collection 配置一致（关键：入库与查询必须同一模型，否则向量对不上） |
| 向量库 | Milvus 2.5（IVF_FLAT / COSINE） | PGVector | 题目没硬性要求；Milvus 可讲"分布式向量检索"，答辩气场更足；Docker compose 一键起，代价可接受 |
| 业务库 | MySQL 8 + MyBatis-Plus | - | 团队熟悉，配套脚手架多 |
| 前端 | Vue3 + TS + Element Plus + ECharts | - | 可视化用 ECharts（趋势线/日历热力图/肌群分布饼图） |

### 1.2 关键决策：对话与 Embedding 分供应商

- `spring.ai.openai.base-url` 在自动配置里对话和 Embedding 共用，指向 DeepSeek 官方后 Embedding 会断
- 解法：`EmbeddingConfig` 手动构建指向硅基流动的 `OpenAiEmbeddingModel`，标记 `@Primary`，Milvus 自动配置自动采用
- 该组合有先例（Gitee 参考项目 wujiang-j/mcp-private-rag-knowledge-base 即 DeepSeek 对话 + 硅基流动 Embedding）

### 1.3 关键决策：不做 MCP 独立进程

- 参考项目把工具写成独立 MCP Server jar、stdio 拉起第二个进程——为演示协议硬凑的架构
- 本系统工具直接写在主应用里（`@Tool` 注解 + `MethodToolCallbackProvider`），单 Java 进程，Agent 编排由 ChatClient 的 ReAct 循环完成
- "可接入 MCP 协议第三方工具"写进论文展望

### 1.4 关键决策：AI 护栏设计（论文创新点素材）

- **NO Math in LLM**：BMI 计算、训练计划编排全部由 Java 确定性逻辑完成，模型只负责对话与工具选择
- **身份不可伪造**：工具方法的用户 ID 从 `UserContext`（JWT 解析写入的 ThreadLocal）获取，模型既看不到也无法伪造，机制上防越权
- **参数护栏**：打卡组数 1-30、次数 1-100 等校验在 Service 层，越界抛错让模型自行纠正重试

## 2. 架构

```
浏览器 (Vue3 + ECharts)
   │  HTTP / SSE
SpringBoot 应用 (单进程)
   ├── 业务模块：用户(JWT) / 体测 / 训练计划 / 打卡
   ├── RAG 模块：Tika 解析 → TokenTextSplitter(500,50) → bge-m3 向量化 → Milvus
   ├── Agent 模块：ChatClient
   │    ├── RetrievalAugmentationAdvisor (topK=5, 检索知识库注入提示词)
   │    ├── PromptChatMemoryAdvisor (窗口 20 条, 按会话ID隔离)
   │    └── FitnessTools 6 个 @Tool (ReAct 循环自主决策调用)
   └── 可视化接口：/api/dashboard/overview 聚合统计 → ECharts
```

## 5. 联调实测记录（2026-11-17）

- **无 Milvus 时后端启动行为（实测）**：`MilvusServiceClient` 启动即主动连接（10 秒超时），连接失败直接导致应用无法启动——不是"聊天才报错"，是整个服务拒绝启动
- **降级方案已落地**：`simple-vector` profile（`SimpleVectorStoreConfig` + `application-simple-vector.yml`），本地 JSON 向量库顶替 Milvus，停机自动持久化；激活方式 `-Dspring-boot.run.profiles=local,simple-vector`；此模式已实测启动成功（2.5s 完成启动）
- **冒烟测试通过**（降级模式）：注册（中文昵称）→ 登录（JWT）→ 录入体测 → 看板聚合返回 → 无 token 请求正确返回 401
- 注意：curl 命令行直接发中文 JSON 在 Git Bash 下会因 GBK 编码导致"请求体格式错误"，测试时中文内容需用 UTF-8 文件 `--data-binary` 发送
- **Spring AI OpenAiApi 的 baseUrl 会自动拼接 `/v1`**：`EmbeddingConfig` 里写 `https://api.siliconflow.cn/v1` 会导致请求打到 `/v1/v1/embeddings` 报 404；正确写法是不带 `/v1` 后缀（application.yml 中 DeepSeek 的配置同理）
- **AI 全链路已实测通过**（simple-vector 模式）：知识文档上传（bge-m3 向量化入库）→ RAG 问答（回答内容基于上传的深蹲知识文档）→ Agent 自主连续调用 4 个工具（查体测→算BMI→生成计划→引用知识库建议）→ 计划落库可在列表查询
- DeepSeek 官方当前模型列表为 `deepseek-flash`（V4.1-Flash）和 `deepseek-v4-pro`，`deepseek-chat` 作为别名自动路由到 flash
- MySQL 为本机 8.0.46（root/root），docker-compose 中容器版 MySQL 已注释（避免 3306 端口冲突），发版脚本已手动执行建库
- Docker/WSL 安装进展：Windows 功能已启用、Docker Desktop 已安装，WSL 本体因网络限速正从 GitHub 慢速下载安装包（后台进行中），装好后切回 Milvus 模式
